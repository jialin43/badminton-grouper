## 1. 背景与目标

### 1.1 背景

羽毛球群报名通常以“微信接龙”形式出现：一段带编号的文本，昵称后加 🌹 表示女生。组织者需要把报名者按 6 人一组拆到不同场地，再手动排版发回群里。整个过程重复、耗时，且容易出现漏人、人数不均、海报不美观的问题。

### 1.2 产品目标

1. **快**：粘贴接龙后 10 秒内完成名单识别与校对。
2. **准**：昵称、女生标记、重复项识别准确，且有可视化校对入口。
3. **顺手**：手机上单手拖拽即可完成分组，不依赖电脑。
4. **好看**：一键生成 1080px 宽的高清海报，微信群中查看清晰。
5. **轻**：纯静态、无后端、无登录，打开即用，数据只留在本机。

### 1.3 成功标准

- 标准格式接龙名单识别率 100%，异常行有明确提示。
- 18 人完成“导入 → 分 3 组 → 出海报”不超过 2 分钟。
- 320px–430px 宽度下无横向滚动、无按钮溢出。
- 海报在微信中可正常预览，并可通过“长按图片”保存。
- 断网后（页面已加载）仍可完成分组与出图。

## 3. 用户流程

### 3.1 主流程

```text
① 导入名单            ② 分组                ③ 生成海报
粘贴接龙 / 选 txt  →  校对名单 → 拖拽分组  →  预览 → 保存/分享
                      设置时间、场馆
```

采用 **3 步向导式单页**，底部固定主操作按钮：

1. **导入名单**：粘贴文本 → 识别 → 校对 → 下一步。
2. **分组**：顶部显示时间/场馆摘要（可展开修改），主体为后补名单 + 小组卡片，拖拽调整。
3. **海报**：实时预览，点击生成/保存，微信内显示长按保存提示。

### 3.2 异常流程

| 场景 | 处理 |
| --- | --- |
| 输入为空 | 按钮禁用 + 提示“请先粘贴接龙内容” |
| 未识别到昵称 | 保留原文，提示检查格式，并给出示例 |
| 部分行未识别 | 展示“未识别 N 行”，可展开查看、手动补录 |
| 昵称重复 | 默认保留第一条，列出重复项，用户可手动补回 |
| 小组已满 | 拒绝放入并提示“该组已满 6 人”，卡片抖动反馈 |
| 刷新页面 | 自动恢复上次进度，顶部提示“已恢复上次编辑” |
| 微信内下载失败 | 展示图片保存层，提示“长按图片保存到相册” |

## 4. 功能需求

### 4.1 名单导入与识别（FR-1）

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-1.1 | P0 | 粘贴微信接龙文本 | 支持多行粘贴，保留换行；输入上限 20,000 字符 |
| FR-1.2 | P0 | 导入 `.txt` 文件 | 按 UTF-8 读取；非文本文件给出错误提示 |
| FR-1.3 | P0 | 解析编号名单 | 支持 `1.` `1、` `1）` `1)` `1：` `1 ` 等前缀 |
| FR-1.4 | P0 | 识别 🌹 女生标记 | 昵称中任意位置的 🌹 均识别，展示时保留玫瑰 |
| FR-1.5 | P0 | 过滤接龙头部信息 | `#接龙`、时间、地点、费用、人数等行不进入名单 |
| FR-1.6 | P0 | 重复昵称处理 | 同名且 🌹 相同才算重复；同名不同 🌹 保留为两人，并列出重复项 |
| FR-1.7 | P0 | 未识别行提示 | 展示行号与原文，支持手动补录 |
| FR-1.8 | P0 | 名单校对 | 可改名、删除、切换性别、手动添加；空名不可保存 |
| FR-1.9 | P0 | 示例数据 | 一键填入示例，便于首次体验 |
| FR-1.10 | P1 | 元信息预填 | 从“时间/地点”行提取建议值，用户确认后写入设置 |

**支持的接龙示例（假设格式）：**

```text
#接龙
10月29日 周四 19:00-21:00 羽毛球
地点：星光羽毛球馆
1. 阿哲
2. 小满🌹
3、Momo
4）大鹏🌹
5. 周予安
6. 阿哲
```

预期结果：识别 5 人（阿哲、小满、Momo、大鹏、周予安），女生 2 人（小满、大鹏），重复 1 条（阿哲），`#接龙`、日期、地点行被忽略。

**解析规则：**

1. 统一换行符，去除零宽字符与首尾空白。
2. 若存在带编号的行，采用“严格模式”：只解析编号行，其余非元信息行进入“未识别”。
3. 若完全没有编号，采用“宽松模式”：所有非元信息行都视为昵称。
4. 去掉行首编号；去掉昵称首尾的标点与空白。
5. 提取 🌹（可多个）→ `isFemale = true`，昵称中去掉玫瑰，海报展示时再补回。
6. 归一化去重：忽略大小写、空格与常见标点，保留首次出现顺序。
7. 过滤纯元信息行与超长行（> 40 字），最多接收 100 人。

**元信息关键词（忽略，不当作昵称）：**

`#接龙`、`接龙`、`报名`、`时间`、`日期`、`地点`、`场馆`、`场地`、`费用`、`人数`、`备注`、`注意`、`共 N 人`、`已报名`。

## 5. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-01 | 每组容量默认 6 人，任何情况下不超过 6 人。 |
| BR-02 | 场次数默认 `floor(总人数 / 6)`；不足 6 人时全部进入后补；允许手动新增空场次。 |
| BR-03 | 每场必须满 6 人；手动拖出的成员进入后补，未满场次在生成海报前提示移入后补。 |
| BR-04 | 每名成员在任意时刻只能属于一个小组或后补名单。 |
| BR-05 | 满员组不能直接追加；需先移出成员，P1 支持拖到成员上交换。 |
| BR-06 | 昵称后的 🌹 表示女生；数据层去掉玫瑰，展示层统一补回。 |
| BR-07 | 重复判断 = 昵称（忽略大小写/空格/标点）+ 🌹 标记；同名但 🌹 不同视为两人。 |
| BR-08 | 空昵称、纯符号昵称不合法；昵称最长 20 个字符（超出提示）。 |
| BR-09 | 时间必须为合法日期，结束时间必须晚于开始时间；未填场馆显示“场地待定”。 |
| BR-10 | 海报是当前状态的快照；修改分组后需重新生成。 |
| BR-11 | 所有数据仅保存在当前浏览器；换浏览器/清缓存会丢失。 |
| BR-12 | 默认顺序 = 接龙报名顺序；随机分组是显式操作，且可撤销。 |

│ │ 2. 小满🌹                │ │

│ 识别到 5 人 · 2 位女生         │

要点：

- 每张成员卡左侧有拖拽把手；把手区域 `touch-action: none`。

- 松手后 200ms 内完成落位；非法落点回弹并 Toast 提示。
- 支持触感反馈（`navigator.vibrate(10)`，不支持则忽略）。
- 拖拽期间禁止页面滚动；非拖拽区域正常滚动。
- 桌面端同时支持鼠标拖拽与键盘操作。

## 7. 技术方案

### 7.1 选型

| 领域 | 选择 | 理由 |
| --- | --- | --- |
| 构建 | Vite | 启动快、静态产物简单、配置少 |
| 框架 | React 19 + TypeScript | 分组/拖拽状态复杂，组件化与类型约束更稳 |
| 拖拽 | `@dnd-kit/core` + `@dnd-kit/sortable` | 触屏、鼠标、键盘统一；支持多容器与自动滚动 |
| 海报 | 原生 Canvas 2D | 输出可控、字体/布局精确、无 DOM 截图误差 |
| 样式 | 原生 CSS + CSS Variables | 体量小，避免 UI 库风格绑架 |
| 状态 | `useReducer` + Context | 单一状态树，便于撤销与持久化 |
| 测试 | Vitest + Testing Library | 解析/分组纯函数易测；组件行为可测 |
| 存储 | localStorage | 纯前端、零配置；配合版本号迁移 |
| 部署 | 任意静态托管 | `dist/` 直接上传；也可内网静态服务器 |

**为什么不使用 html2canvas：** DOM 截图在字体加载、Emoji 渲染、跨域图片和移动端缩放上不稳定；原生 Canvas 可以精确控制 1080px 输出与文字截断，海报质量更可控。

**为什么不使用 UI 组件库：** 页面结构简单，定制视觉需求强；引入组件库会增加体积与覆盖样式的成本。

### 7.3 数据模型

```ts
type Step = 1 | 2 | 3;

}

```

约束：`players` 的 id 唯一；`groups[].playerIds` 与 `unassignedIds`（后补名单）的并集恰好等于全部玩家，且互不重复；每场长度 ≤ 6，只有满 6 人的场次会进入海报。

### 7.4 解析器设计

```ts
interface ParseResult {
  players: Player[];
  duplicates: { name: string; lines: number[] }[];
  ignored: { line: number; text: string; reason: string }[];
  mode: 'numbered' | 'plain';
}

function parseSignup(text: string): ParseResult;
```

处理流水线：

1. `normalize`：CRLF → LF，去零宽字符，逐行 trim，丢弃空行。
2. `classify`：识别元信息行、编号行、普通行。
3. `select`：有编号行则只取编号行（严格模式），否则取普通行（宽松模式）。
4. `extract`：去编号、去首尾标点、提取 🌹、压缩空格。
5. `validate`：长度、空值、纯符号、人数上限。
6. `dedupe`：归一化 key 去重，记录重复行号。
7. `return`：保留原始顺序，附带统计与警告。

编号正则（按顺序尝试）：

```ts
/^\s*(\d{1,3})\s*[.、．)）:：]\s*(.+)$/u
/^\s*(\d{1,3})\s+(.+)$/u
```

玫瑰识别：`/[\u{1F339}]/gu`；去除后 `trim()`。昵称中的其他 Emoji 保留。

### 7.5 拖拽实现

- 使用 `DndContext` 包裹“后补名单 + 所有小组”，每个容器一个 `SortableContext`。
- 传感器：
  - `PointerSensor`：鼠标/触控笔，移动 5px 激活。
  - `TouchSensor`：延迟 120ms、容差 8px，避免与滚动冲突。
  - `KeyboardSensor`：空格拿起、方向键移动、回车放下。
- 每张卡片提供独立拖拽把手（`⠿`），把手设置 `touch-action: none`。
- 跨容器放置规则：
  - 目标为成员卡：插入到该成员前/后。
  - 目标为容器空白：追加到末尾。
  - 目标组已满：拒绝，状态不变，Toast + 抖动。
- `DragOverlay` 渲染浮层，原卡片保留半透明占位。
- 自动滚动由 dnd-kit `autoScroll` 处理，边缘阈值约 80px。
- 每次成功移动前保存快照，供撤销使用；撤销栈上限 30。
- 兜底交互：点击卡片打开“移动到…”底部面板（P1）。

### 7.6 海报布局与渲染

**尺寸：**

- 画布宽 `1080px`，四周安全边距 `64px`。
- 头部约 `300px`：眉题、主标题、日期时间、场馆。
- 小组卡片：2 列，间距 `24px`，单卡宽 `464px`；组数 ≤ 2 时改为单列。
- 每卡：组名 + 人数 + 成员列表（每行 2 人，最多 3 行）。
- 页脚：总人数、组数、每组人数、女生人数、生成日期。
- 高度动态计算：`max(1440, 头部 + 卡片行数 × 卡高 + 间距 + 页脚)`。

**绘制策略：**

1. `layout.ts` 先根据组数、名字长度计算所有文本块与卡片坐标，返回纯数据布局树（可单测）。
2. `render.ts` 按布局树绘制：背景 → 头部 → 卡片 → 成员 → 页脚。
3. 字体加载完成后（`document.fonts.ready`）再绘制，避免字体回退。
4. 名字超宽时先缩字号（38 → 30px），仍超宽则截断加省略号。
5. 🌹 使用 Emoji 字体栈：`"Apple Color Emoji", "Segoe UI Emoji", "Noto Color Emoji"`；若真机显示异常，降级为矢量玫瑰图形（P1）。
6. `canvas.toBlob('image/png')` 导出；导出前按钮进入 loading，避免重复点击。

### 7.7 状态与持久化

- `useReducer` 管理单一状态树；所有变更通过 action，便于撤销与测试。
- 自动保存：状态变化后 300ms 防抖写入 `localStorage`，key 为 `badminton-grouper:v1`。
- 启动时读取并校验：版本号、玩家 id 唯一、分组引用完整、容量合法；异常则备份原始数据到 `...:backup` 后重置。
- 恢复提示：顶部 Banner 显示“已恢复 10-29 18:20 的编辑”，可一键清空。
- 重置需二次确认；清空后保留页面与示例入口。

### 7.8 兼容性、性能与安全

- 目标浏览器：iOS Safari 15+、Android Chrome 110+、微信内置浏览器（X5/XWeb）、桌面 Chrome/Edge/Safari 最近两个大版本。
- 移动端：`100dvh`、`env(safe-area-inset-bottom)`、`visualViewport` 处理键盘遮挡。
- 性能目标：100 人以内解析 < 50ms；拖拽保持 60fps；海报生成 < 500ms。
- 安全：React 自动转义昵称；Canvas 只绘制文本；不拼接 HTML；输入长度限制 20,000 字符。
- 隐私：无网络请求、无埋点、无第三方字体；页面可离线使用（刷新除外）。
- 可访问性：按钮 ≥ 44×44px、表单有 label、Toast 使用 `aria-live`、支持减少动态效果。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
